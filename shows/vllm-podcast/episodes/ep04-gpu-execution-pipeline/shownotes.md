# 第 4 期：一行 Python，一段录像——模型是怎么变成融合 kernel 的

> 判据不是「编译优化跑得快不快」，是「跨 GPU 架构的表现一不一致」。

## 本期简介

你在 Python 里写了一个 attention 层——一行 scaled dot product attention。vLLM 把它变成了一段在 CUDA graph 里反复重播的融合 kernel，中间连 Python 解释器都不经过。更刺激的是：vLLM 自己用 Triton 写的 attention 后端，约 800 行代码，在 H100 长 decode 场景下跑出了 FlashAttention 3 约七万行 C++ 的 100.7% 性能——比百分百还多零点七。

本期两条线走完：一条是这一行 Python 怎么变成录像（worker 生命周期、CustomOp 两级 dispatch、torch.compile 分片编译、图捕获与重播），一条是录像重播要付什么钱（冷启动上百秒、固定形状空转、Blackwell 上的性能倒退）。怎么做到的，代价是什么——账听完自己算。

## 本期要点

- **指令怎么到 worker 手上**：执行器按一个配置字符串三选一——uni 单进程、mp 多进程、ray 分布式，一个字符串定生死。mp 模式拉出 N 个 worker 子进程，出生五步走：占位（延迟出生，不养闲人）→ 初始化设备 → 装载权重 → 发 READY → 进忙循环接指令
- **collective_rpc 广播**：引擎所有指令统一成一次广播，像开会喊一嗓子，全组同时开工；回复按发出顺序收回，不会串账；下班三级关停：优雅排空 → SIGTERM → SIGKILL，先礼后兵，每级是给前一级留的补救机会
- **execute_model 阶段一**：先干三件事——调和持久批次状态（调度变更单对上 worker 快照）、把二维批次拍扁成一维 token 序列、装配注意力元数据（每颗 token 的笔记住哪块显存）；前向一发完就把产出塞进 ExecuteModelState 盒子（十个字段）立刻返回，CPU 不等 GPU，GPU 不等采样
- **模型长什么样**：Llama 四级嵌套，俄罗斯套娃——语言模型头、模型主体、解码层、每层里注意力+前馈两个子模块，每级都能单独换；所有子模块统一构造契约：(vllm_config, prefix) 两个参数，前缀是门牌号，登记制注册，权重装载时几百个张量对着户口本找家
- **注意力统一封装 = 酒店标准间**：模型只管调「注意力」，背后是分页注意力、FlashAttention 还是 Triton 后端一概不知——后端多、模型更多，让每个模型去适配每个后端，组合就爆炸了；标准间一统，换供应商不动图纸
- **CustomOp 两级 dispatch**：预制菜（forward_cuda 预编译融合内核，出餐快但后厨看不见）vs 现炒（forward_native 纯 torch 算子链，每一步摆在桌面上）；构造时按硬件选死、运行时零开销转发。反直觉的规矩：编译开着默认走现炒——编译器看得见才融得动
- **分片编译**：模型类套上可编译外壳，guard（形状核对）整个扔掉——要的就是固定形状；首次前向切图：在 attention 处一刀两段，普通段（线性层、归一化、残差）交给 Inductor 编译再包图捕获，attention 段保持原样跑自家融合内核——标准件走流水线，特殊件手工精做
- **录像与重播**：图捕获把一串 GPU 命令完整录下来，每拍原样放一遍；挑观众靠批次描述符——token 数、这一拍是不是清一色 decode、有没有挂 LoRA，三样拼成一把钥匙；三级分派：FULL 完整录像请求数精确匹配、PIECEWISE 分段录像形状差不多就放、NONE 逐算子老实跑——录像是个优化，不是保证
- **录像的代价**：固定网格按录的时候的最大配置启动，工作量小了也照跑——空转就是 100.7% 的另一半账；地址必须一致，捕获时占的显存重播时必须还在原位；PAD_SLOT_ID 占位槽位给没填满的行派假地址站岗，块表双镜像 CPU 记账、GPU 干活、攒批同步
- **争议账本**：Inductor 分区方案 2-10% 提升 vs 冷启动编译 2-5 倍（大模型实测 100 秒）、大量 monkeypatch、attention+量化融合在 Blackwell 上甚至倒退；社区最终默认不启用分区方案，改用优化级别分层。分片编译里做不了原地归约——编译器这道天花板，vLLM 绕不过去
- **判据**：不是「编译优化跑得快不快」，是「跨 GPU 架构的表现一不一致」。Inductor 在 H100 上可行、在 Blackwell 上倒退——赌得起就编，赌不起就退回纯 torch，让编译器跟新硬件慢慢磨合；CustomOp 的二级 dispatch 就是把开关交到你手上，不替你赌
- **「我不知道」**：Blackwell 上 attention+量化融合为什么倒退——issue 里有复现、有现象，根因社区还没查清

## 引用的社区声音

- **@ProExpertProg（GitHub issue #27080，2025-10）**：Inductor 分区方案带来 2-10% 性能提升，但冷启动编译时间增加 2-5 倍，实测大模型可达 100 秒；需要大量 monkeypatch 和 workaround，attention+量化融合在 Blackwell 上甚至出现倒退
- **vLLM 官方论坛（2025-11）**：分片编译里为什么不能做原地归约？编译路径下的自定义算子不能安全支持原地修改——会破坏计算图假设和别名分析，编译器没法可靠推断张量生命周期

## 下期预告

GPU 每拍算出 128000 个 logits——但选哪一颗 token 出门，不是挑个概率最大的就算完，还要过九道关卡。其中一道，把你写的 JSON Schema 实时编译成一张 GPU 位掩码，在采样之前就把非法 token 的概率精确打成零。不是模型学会了 JSON，是内核不让它犯错。下一期，采样管线的最后一站。
