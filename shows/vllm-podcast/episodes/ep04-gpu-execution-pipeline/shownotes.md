# 第 4 期：一行 Python，一段录像——模型是怎么变成融合内核的

> 判据不是「编译优化跑得快不快」，是「跨显卡架构的表现一不一致」。

## 本期简介

你在 Python 里写了一个注意力层——一行调用，名字老长，什么 scaled dot product attention。vLLM 把它变成了一段在 GPU 上反复重播的「录像」，中间连 Python 解释器都不经过。更刺激的是：vLLM 官方拿 Triton 写了个注意力后端，大约 800 行代码，在 H100 长 decode 场景下跑出了 FlashAttention 3 约七万行 C++ 的 100.7% 性能——比百分之百还多零点七。

本期两条线走完：一条是这一行 Python 怎么变成录像（worker 生命周期、CustomOp 两级 dispatch、torch.compile 分片编译、图捕获与重播），一条是录像重播要付什么钱（冷启动上百秒、固定形状空转、Blackwell 上的性能倒退）。怎么做到的、代价是什么——账听完自己算。

## 本期要点

- **指令怎么到 worker 手上**：执行器按一个配置字符串三选一——uni 单进程、mp 多进程、ray 分布式，一个字符串定生死；写错了启动直接报错，不会默默跑歪。mp 模式拉出一群 worker 子进程，出生固定流程：占位（延迟出生，不养闲人）→ 初始化设备 → 装载权重 → 发 READY → 进忙循环接指令
- **collective_rpc 广播**：引擎把所有指令统一成一种调用，像开会喊一嗓子，一条消息同时发给所有 worker，全组同时开工——张量并行下同一步计算谁慢了谁拖全组；回复按发出顺序一个个收回，不串账。下班三级关停：优雅排空 → SIGTERM → SIGKILL，先礼后兵，每级是给前一级留的补救机会
- **execute_model 阶段一**：先干三件事——对账（拿调度器这拍的变更单，跟手里快照对齐）、把「一行一个请求」的二维批次拍扁成一维 token 序列、装配注意力元数据（每颗 token 的笔记住哪块显存）；发起前向前验明正身：那个十个字段的盒子必须是空的。发完就返回，CPU 不等 GPU——甩手去规划下一拍，这就是两阶段解耦的全部理由
- **模型长什么样**：Llama 四级嵌套，俄罗斯套娃——语言模型头、模型主体、几十个解码层、每层里注意力+前馈两个子模块，每级都能单独换；所有子模块统一构造契约：一个配置、一个名字前缀。前缀是门牌号，登记制注册，装载权重时几百个张量对着户口本找家
- **注意力统一封装 = 酒店标准间**：模型只管调「注意力」，背后是分页注意力、FlashAttention 还是 Triton 后端一概不知——后端多、模型更多，让每个模型去适配每个后端，组合就爆炸了；标准间一统，换供应商不动图纸，模型定义跟 GPU 执行就在这儿解耦
- **CustomOp 两级 dispatch**：预制菜（forward_cuda 预编译融合内核，出餐快但后厨看不见）vs 现炒（forward_native 纯 torch 算子链，每一步摆在桌面上）；构造时按硬件平台一次选死、之后零开销转发。反直觉的规矩：编译开着默认走现炒——编译器要看见全过程才能通盘优化；用户点名要某个算子的融合版，才切预制
- **分片编译**：模型类套上可编译外壳，guard（形状核对）整个扔掉——要的就是固定形状；首次前向触发自家编译后端，第一件事切图：在注意力算子处一刀下去，注意力一段、剩下一段。普通段交给 Inductor 编译再包图捕获，注意力段保持原样直接跑——它有自己的家底，各家后端的融合内核早就备好了。切的是图，断的不是数据；之后每次前向走缓存
- **录像与重播**：把一串 GPU 命令完整跑一遍录下来（捕获），之后每拍原样放一遍（重播），省掉每步启动内核的开销；录像形状定死、连显存地址都得一致。挑观众靠批次描述符——token 数、这一拍是不是清一色 decode、有没有挂 LoRA，三样拼成一把钥匙；三级分派：完整录像请求数精确匹配、分段录像形状差不多就放、都不行或超过捕获上限就逐算子老实跑——录像是个优化，不是保证
- **录像的代价**：空转——放的时候按录的时候的最大配置启动，这拍实际工作量小了，多余的部分照跑；亏与不亏，是拿空转跟启动开销比出来的。块表那对双镜像（CPU 记账、GPU 干活、攒批同步）今天被录像绑得更紧：Triton 内核按「块号乘块大小加块内偏移」算出槽位，没填满的行尾巴拿占位符补齐——不指向任何真块，纯站岗，伺候的就是录像的固定形状
- **争议账本**：Inductor 分区方案 2% 到 10% 提升 vs 冷启动编译时间增加 2 到 5 倍（实测大模型可达 100 秒）、大量猴子补丁和绕行手段、注意力加量化的融合在 Blackwell 上甚至倒退；社区后来干脆默认不启用这个分区方案，改用优化级别分层——想激进，自己往上开。分片编译里也做不了原地归约：原地改会破坏计算图假设和别名分析，编译器这道天花板，vLLM 绕不过去
- **判据**：不是「编译优化跑得快不快」，是「跨显卡架构的表现一不一致」。Inductor 在 H100 上可行、在 Blackwell 上倒退——编译在赌架构，CustomOp 在留退路：赌得起就编，赌不起退回纯 torch，让编译器跟新硬件慢慢磨。开关交你手上，不替你赌
- **本期也没搞清楚的事**：Blackwell 上注意力加量化融合为什么反而倒退——issue 里给了现象、给了复现，根因社区还没定论。评论区有懂的，说说你的分析

## 下期预告

GPU 每拍算出 128000 个 logits——十二万八千个词的打分。但最终选哪颗 token 出门，不是挑个分最高的就完事，还要过九道关卡。其中一道最离谱：你让模型输出 JSON，它把你写的 JSON 格式说明实时编译成一张 GPU 上的位掩码，在采样之前就把非法 token 的打分精确打成零。不是模型学会了 JSON，是内核不让它犯错。下一期，采样管线的最后一站，九道关卡一道一道过。
