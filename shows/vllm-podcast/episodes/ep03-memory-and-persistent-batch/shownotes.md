# 第 3 期：你省的不是 token，是物理块——一块显存的一生

> 淘汰了 90% 的不重要 token，重启服务，显存几乎没降——因为显存是按「块」还的，不是按 token 还的。

## 本期简介

一道面试题开场：你给 vLLM 加了 KV cache 压缩，淘汰了 90% 的不重要 token，重启后显存几乎没降，同样的长度照样爆显存。答案不在淘汰了多少 token，在淘汰的单位——KV cache 被切成 16 token 一块的物理块，只要一块里还剩一颗 token，整块就释放不了。

本期顺着这块显存走完一生：从块池出发，经过 LRU 排队、前缀缓存共享、分配失败被抢占，住进跨拍存活的持久批次，最后被块表送进 GPU。机制讲完，围绕「16 这个块大小到底谁定的」打了一场社区争议。

## 本期要点

- **为什么切块**：KV cache 是活的，随对话长度只增不减，长上下文下是显存大头；按最长长度给每个请求预分配，短请求占着长位子，空着的比住着的还多，还怕碎片——vLLM 从操作系统偷了虚拟内存的主意，切成 16 token 一块，散落的块由 PagedAttention 算子按块寻址
- **块池与空闲队列**：全局块管家管三样家当——块的名单、空闲块队列、前缀缓存查表；空闲块串成双向链表，头尾各站一个哨兵，队头最久没用先被赶，链表写在块自己身上、中间删除 O(1)；驱逐是惰性的，不够了才赶，被赶只是「可分配」不是销毁，哈希钥匙同步删
- **前缀缓存**：满 16 颗 token 的块才算哈希当钥匙（不满的块内容还在长，缓了白缓），沿哈希链找最长前缀命中；刻意不去重——同一把钥匙可对应多块，拿一块显存换块表只增不改；引用计数归零才真正还块，计数出了 bug 就是泄漏
- **三段式分配**：先释放滑动窗口外的旧块 → 挂前缀命中块（本地缓存和 PD 分离外部送来的，一视同仁）→ 开新块 + lookahead 提前占位；失败是「这拍发不出来」的正常返回值，不是异常
- **抢占与双队列**：分配失败触发抢占循环——拽下 RUNNING 队尾、块归还、状态打回、回队头插队补偿，本拍不再放新请求；token 预算不够又没被抢的请求挪进 skipped waiting 独立侧道，不许堵队头，防队头阻塞
- **持久批次**：请求批不每拍重建——一行一请求的全长容器（CPU 侧记账板，不是 GPU 笔记），每拍发「变更单」差量更新，worker 拿快照就地改；请求退房留洞、新客填洞、洞攒多了才压实；赌的是「大部分请求活着跨拍」
- **块表最后一公里**：CPU/GPU 双镜像，改了先改 CPU 这份，攒够了一次性 commit 批量同步；Triton 内核把「逻辑块号 × 16 + 块内偏移」翻译成物理槽位，尾部占位符补齐适配固定网格——固定网格牵扯到 CUDA graph，是下期的账
- **争议判据**：块大小 16 不是圣旨，是某组约束下的折中——唯一 prompt 场景分页只有碎片没收益、块越小越好；多租户 Agent 场景（150 个客户、每客户 6000 token 共享系统提示词）前缀缓存收益是 170 倍的差距，不是块大小能换回来的。选块大小，本质是判断你的负载属于哪种
- **本期也没搞清楚的事**：16 这个数到底怎么定出来的——书里只有「默认 16」的实现事实，论文是实验选的，换个硬件、换个负载还成不成立，我们说不准；GQA 下内核重复加载的帖子是去年三月的，内核迭代过几轮，现在什么样不敢替人打包票。评论区有懂的，说说你们的块大小怎么选的

## 引用的社区声音

- **腾讯云开发者社区（2026-06）**：KV cache 压缩淘汰 90% token 显存没降——答案在释放了多少个完整物理块，一块还剩一颗 token 就释放不了
- **CSDN 博主转述群友面经（2025-08）**：面试官让手写 PagedAttention 的实现逻辑，再讲它跟 KV cache 的区别和优化点，群里一位同学当场被问懵——转述未核实，但「手写 PagedAttention」能进面试题，说明切块是理解 vLLM 的入场券
- **牛客面经（2026-03）**：前缀缓存是 AI Infra 实习岗的当场考点，这类追问一般会细到——哈希粒度是什么？不满一个块的前缀能不能缓存？系统提示词固定但用户 query 不同时命中率怎么估
- **牛客面经转述面试官递进追问（2026-06）**：块大小设为 1，碎片没了但块表暴涨；设太大短序列场景严重浪费；默认 16 一块只用 15 颗，剩下一个空位就浪费——内部碎片
- **GitHub issue @wenqiny（2025-03）**：分组查询注意力（GQA）下 8 个线程块重复加载同一份 KV 头数据，L1/L2 之间流量跑了 800 多 MB、实际 KV 数据只有 64 MB；他给的新内核性能提升约三成
- **Mistral AI 生产环境（2026-06）**：UCX 钩子和前缀缓存里的请求引用循环导致 CPU 内存泄漏，GPU worker 进程内存溢出被杀——社区已按根因修复，但生产内存还得自己盯监控
- **llm-d 团队 benchmark（2026-04）**：16 块 H100 跑 Qwen-32B、150 个客户各 6000 token 共享系统提示词，前缀缓存感知调度把 P90 首 token 延迟从 93 秒降到 0.542 秒——170 倍（单机专门场景的最有利条件，真实负载打折扣但量级不骗人）
- **FutureAGI 评估（2026-04）**：KV cache 命中率低于 0.55 时，RAG 应用 Groundedness 评分从 0.88 跌到 0.69，工具调用参数开始丢失——命中率低不只是慢，是模型开始犯傻（第三方评估，非同行评审）
- **llm-d 团队（2026-04）**：单实例里首 token 延迟从 4.3 秒降到 0.6 秒；但挂上传统负载均衡器，相同前缀被分散到不同机器，缓存反复被驱逐重算——分布式前缀缓存还不是开箱即用，要拿得自己搭全局索引

## 下期预告

块表映射只是 vLLM 里几十个自定义算子中的一个。下一期把镜头推到 GPU 上：一个写在 Python 里的模型层，怎么变成一段在 CUDA graph 里反复重播的融合内核——中间连 Python 解释器都不经过。「固定网格」四个字，下期揭晓。
