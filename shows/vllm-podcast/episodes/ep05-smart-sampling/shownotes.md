# 第 5 期：128000 个分数，只放一颗出门——采样管线的最后一站

> 判据只有一条：在你的 GPU、你的格式复杂度下，掩码的填充加传输，能不能被前向计算完全遮盖。遮得住，结构化输出就是免费的；遮不住，它就是真的慢，别硬吹。

## 本期简介

GPU 每拍算出 128000 个 logits——十二万八千个词的打分，最后只放一颗 token 出门。从打分到出门这最后一步，要过九道关卡：抢救原始概率、偏置、禁词、长度门槛、三种惩罚、min p、温度、top-k/top-p 截断、两条避开同步的抽样路。更刺激的是闸门：你让模型输出 JSON，引擎把你写的格式说明实时编译成一张 GPU 位掩码——十二万八千个判决压成 4000 个 32 位整数，采样之前就把非法 token 的打分打成负无穷。还有投机解码：拿个便宜小模型先猜好几颗，大模型一次验证，猜对了白赚速度——但社区系统实测发现，验证本身占了总运行时间的 42% 到 95%。

本期三条线走完：九步采样管线一道一道过、语法位掩码从编译到上卡的全链路、投机解码的验收数学与隐藏成本。这也是季终期——五期走完，一个请求从进门到一颗 token 出门，这条路到头了。

## 本期要点

- **两阶段解耦入口**：execute_model 发起前向、当场返回空，logits 装进那个十个字段的盒子（ExecuteModelState）；等引擎腾出手，sample_tokens 开盒采样。盒子单槽、断言锁两头：前向开跑前必须空、取货前必须非空，严格配对。中间的空档引擎去排下一拍——跑腿的先出门，拍板的等货到再上场
- **prefill 余账销账（上期挂账，本期还清）**：录像重播要形状固定、地址固定。decode 清一色一颗 token、形状稳，吃得到红利；prefill 的 prompt 有长有短、形状回回不一样，对不上录像，只能回退 NONE 档逐算子老实跑
- **九步管线归拢成四类活**：留底（趁各道工序没动手，先把原始概率整个存下来，要 logprobs 的请求拿原图当「你凭什么选这个词」的证据）、改分（五道处理器）、分路（贪心快路 vs 随机路）、交卷（把原始概率的 top-k 收集回来，开头留的底这会儿用）
- **改分区五道，分叉在「动不动得了冠军」**：偏置直接改分、禁词精确封杀一票否决（只在快补全成禁词时动手）、min tokens 没凑够长度禁止发结束符、三种惩罚照 OpenAI 定义算（频率累计扣/存在扣一刀/重复专打复读机）——这四道能换冠军，必须在贪心快路之前跑完；第五道 min p 砍掉概率明显垫底的尾巴、砍谁都不影响冠军（argmax 不变），留到温度之后、随机路上再生效
- **贪心快路的规矩**：整批全贪心，温度都不上、直接选最大；只要一个请求要随机，整批走随机路——这一拍走哪条道，由最「不贪心」的那个决定。随机路上：温度（越低越认死理，越高越野）、min p、top-k/top-p 截断（数人头 vs 看分量，卡上备了好几套后端、构造时绑死）、抽样两条路（random_sample 和 flashinfer，都为避开 GPU 停下来等 CPU 的同步）
- **语法位掩码：约束不改采样，只加一层掩码**：JSON 约束编译成状态机，每吃一颗 token 跳一个状态，「允许」翻译成 0/1 掩码；一个 32 位整数装 32 个词的判决，十二万八千个词一行四千个整数。非法 token 的打分原地写成负无穷——为什么必须是负无穷而不是大负数：大负数温度一缩可能又被拉回可选范围，负无穷在任何变换下概率都是零。拉黑跟不回消息的区别
- **编译不堵调度（第二期挂的账，挂了三期，本期还清）**：格式约束编译成状态机可能上百毫秒——根本不进调度循环，扔进线程池异步做，请求先进等候区（waiting for structured output grammar）；引擎每拍顺路瞄一眼、只等 0.1 毫秒，没熟就回去干活。死等是线程睡着，瞄一眼没代价
- **六种约束归一成一个编译键**：json、正则、choice、grammar、json object、structural tag。最绝的是 choice——校验期被原地改写成一段 EBNF，请求到引擎时 choice 字段清空、grammar 字段填好：你交请求那一刻参数就被原地改造，引擎收到的从来不是你写的原版
- **状态机六方法契约**：接收（正式推进）、试走（只验不推，给草稿做预检）、倒带（投机被拒时退回，上限跟草稿长度绑定）、填掩码、判终、重置——试走与倒带这一对，是语法和投机一起开的钥匙
- **掩码落地分两头**：调度侧按请求装配，投机时每个草稿位置占一行、不受约束的行整行填 -1 全放行；批量超 128 才建线程池并行填充（16 行一组、每行独写），没过 128 纯走串行——线程不是免费的。worker 侧预分配卡上缓冲，独立 copy stream 异步搬上卡，传输跟前向两头并进。默认路径把掩码摊平交给 xgrammar 库函数；自写 Triton 内核拆位那条是 V2 路径，默认关
- **投机解码的验收数学**：草稿两类来源——n-gram 纯 CPU 抄作业（KMP 找最长匹配的重复片段，抄后续词）、模型类（EAGLE、MTP 吃大模型中间状态跑小模型前向）。变长草稿用几组下标间接对齐塞进一个批次，大模型只跑一次前向；验收逐颗比概率，够高接受白赚、不够拒绝。命根子在拒绝时：从残差分布（两个分布相减、负数归零）补采一颗——有这一步，输出分布跟压根没用投机一模一样。加速可以，绝不许改变模型说话的习惯
- **争议账本（批判必须有靶子）**：vLLM 官方论坛版主承认结构化输出整体比无约束解码慢、瓶颈在 CPU-GPU 同步，xgrammar 在 RTX 4090 上因同步开销反而比 outlines 还慢；SqueezeBits 评测发现 XGrammar 在动态复杂格式下被 LLGuidance 反超，且不少能编译的格式被 vLLM 集成层拒掉——能编译和能集成之间隔着一条缝；MLSys 论文实测验证开销占总运行时间 42% 到 95%、批越大加速比越缩；GitHub 有报告草稿接受率一低生成反而变慢；还有一个报告者自追根因、官方未确认的 bug：动态投机解码关掉后，草稿模型每步还在跑一次完整前向——「已关闭」的判断发生在草稿前向之后，关了个寂寞
- **量化补刀**：700 亿参数的 Llama 3.3，FP16 下函数调用评分 0.91，AWQ 的 INT4 量化后跌到 0.78；JSON 遵守率从 0.94 跌到 0.83——自由文本几乎没退化，专咬结构化输出一口。拿 INT4 跑 Agent 的活，可能恰恰在最需要精确的地方悄悄降级
- **本期也没搞清楚的事**：草稿猜多长、接受率做到多少才划算，跟模型、批大小、硬件全缠在一起，书里也没给能抄的答案；量化为什么专咬结构化输出，原理也没完全吃透。两处都挂了问号——评论区有懂的，说说

## 引用的社区声音

- **SqueezeBits 团队系统评测（2025-09）**：XGrammar 在简单重复格式下吞吐最高，动态复杂格式下被 LLGuidance 反超；而且 XGrammar 能编译的格式，不少被 vLLM 集成层拒掉，实际可用覆盖率低于编译数字
- **vLLM 官方论坛版主（2025-10）**：结构化输出整体比无约束解码慢，瓶颈在 CPU 和 GPU 的同步——状态机允许的 token 列表翻译成 GPU 掩码张量这一步就是瓶颈；xgrammar 在 RTX 4090 上因同步开销反而比 outlines 还慢；真正异步的处理还在开发中
- **GitHub issue（2025-04）**：草稿接受率一低，生成反而变慢——同时为两个模型付费，几乎没收益；这事到现在还有跟踪单在跟
- **Aleksa Gordic 的 vLLM 剖析长文（2025-09）**：V1 当时没走 LLM 级草稿模型，用 n-gram、EAGLE、Medusa 这些更轻的方案；n-gram 首次匹配就返回，带「最近偏差」
- **牛客面经（2026-06）**：MTP 多 token 预测的大致流程？实测接受率多少？优化的是首 token 延迟还是逐 token 延迟？引入额外计算，为什么吞吐还能涨？——面试追问到接受率这层，靠背概念接不住
- **牛客面经（2026-07）**：字节覆盖推理优化、推荐、多模态，考系统化思维；腾讯偏重推理框架，vLLM 和 PagedAttention 是独立高频考点，面腾讯得把源码啃透
- **MLSys 2026 Oral 论文（2026-01）**：批大小 1 时 EAGLE 加速 1.73 倍，批涨到 128 只剩 1.21 倍；700 亿参数的 Llama 3 上从 1.96 倍掉到 1.72 倍；验证开销占总运行时间 42% 到 95%——投机解码真正的瓶颈不是草稿准不准，是验证本身
- **GitHub issue（2026-07）**：一台 GB10 机器上，动态投机解码在批大小跨过阈值后把投机关了，吞吐从每秒 232 颗掉到 24 至 157 颗，整批墙钟时间从 6.3 秒涨到 40 至 60 秒；报告者追到的根因：就算投机已关，草稿模型每步还在跑一次完整前向（官方尚未确认，修复也没影）
- **FutureAGI 评测（2026-04）**：700 亿参数的 Llama 3.3，FP16 下函数调用评分 0.91，AWQ 的 INT4 量化后跌到 0.78；JSON 遵守率从 0.94 跌到 0.83；自由文本几乎没退化

## 季终收束

五期走完，从一个请求进门到一颗 token 出门。回头看，每一站背后好像是同一个句式——不是「这样更好」，是「不这样就跑不动」：拆三段，不是好玩，是不拆 GPU 就饿着；数 token 不数请求，不是公平，是不这样 GPU 吃不饱；KV cache 切成页，不是省事，是不切就爆显存；Python 编译成录像，不是炫技，是 Python 太慢；JSON 约束变成位掩码，不是花活，是模型自己守不住规矩。

下次你让模型吐一段 JSON，记住——不是它学会了规矩，是它身后有一整个引擎，在替它把关。从一颗 token 出发，看见一个引擎的全部汗。这季就到这里，下季见。
